# Release-readiness review, 2026-11-13

Reviewer: Claude Fable 5.2, on branch `claude/fable-review-654018` (cut from `fix/apply-vm-trial-findings`, commit `1a66ebf`).

Scope: `skills/neurotune/SKILL.md`, `skills/neurotune/references/*.md`, `skills/neurotune/scripts/*`, and the tests that cover them. Files owned by the coordinating session (README, CHANGELOG, `docs/*`, AGENTS.md, SECURITY.md, package version) were read but not edited; changes for them are in [Suggested changes](#suggested-changes-for-files-i-did-not-edit).

Line numbers refer to the files as they are at the last commit of this branch.

## Verdict

Nothing found that should block a beta launch once this branch is merged. Three things should be settled before the announcement, all in files the coordinator owns or decisions the user owns:

1. **The README overstates Apply testing for 0.3.0** (S2, S3 below). The 0.3.0 categories (devices, MSI/affinity, network adapter settings, BCD, Memory Integrity, driver packages, Store apps) and the failure paths were run in the VM by hand, following `apply.md`. No model reading the skill has applied them yet. The README should say so.
2. **Decide what happens when a user insists on disabling Defender, the firewall, UAC or Windows Update** (O1). Today the skill applies it after a separate confirmation.
3. **The instruction changes on this branch have not been run by a model or in the VM.** They add guardrails and do not remove any, so the regression risk is low, but they are text edits reviewed by reading.

## How this was checked

- Read every file in scope in full, plus README, SECURITY.md, AGENTS.md, ARCHITECTURE, ROADMAP and the two most relevant eval cases.
- `npm test`: 94 tests, 93 pass, 1 skipped (POSIX-only), 0 fail. `node scripts/check.mjs`: pass. `npm run test:package`: pass, 44 files.
- The edited lines of `Measure-Latency.ps1` were parsed and exercised in Windows PowerShell 5.1 on temporary files (summary with the line, without it, missing file). The old code was confirmed to fail with "Cannot index into a null array" when the line is absent.
- `{current}` passed bare from PowerShell to a native command was confirmed to arrive as `-encodedCommand …` (tested with `cmd /c echo`, not with `bcdedit`).
- Two findings were confirmed against saved trial output in `evals/results/` (read only): the VM scan summary listed `WinDefend`, `WdNisSvc`, `MDCoreSvc` and `edgeupdate` under `thirdPartyActive` and contained 7 account SIDs. The trace arithmetic was checked against the real 16-CPU report (`dpcTimePercent` equals the per-CPU sum divided by 16).
- Not done: no VM run, no kernel trace, no system-changing command, no model run with the new instructions. The exact folder layout of `pnputil /export-driver` for a single package was not verified; the per-package folder is safe under either layout.

## Findings fixed on this branch

| ID | Where | Problem | Fix |

| F1 | `scripts/system.mjs:15`, `:141` | `services.thirdPartyActive` was chosen by install path only (outside `C:\Windows`). | F2 | `references/apply.md:60` | All exported driver packages went into one `<dir>\drivers` folder. ## What looked right

- The CLI passes arguments as arrays to a fixed PowerShell path with fixed script names; no shell, no text from reports reaches a command line.
- Reports are written exclusively, never overwritten, with linked ancestors and alternate data streams refused; seals are re-derived on every read.
- `proposal-check` cannot produce an approval: `approvalGranted` and `executable` are constants, `backup.verified: true` is rejected, unknown fields are rejected.
- `Collect-Hardware.ps1` still matches its pinned hash and only reads. `Collect-System.ps1` only reads. `Measure-Latency.ps1` refuses to start when a kernel session exists and stops only the session it started.
- The latency arithmetic is correct on real data (16 CPUs), and driver names are length-bounded and control-character-free before they become facts.
- Consent, "data is not instruction", "only the human's messages confirm" and "no reboot" are stated in SKILL.md and repeated where they apply.
