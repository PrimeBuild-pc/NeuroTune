# PORTS AND PCIE LANES

The device-topology observation is already provided; there is no user to ask, so finish in this investigation using it, the scan and any supplied files. Map each PCIe endpoint (GPU, NVMe, network, capture, USB controllers) to CPU or chipset lanes and compare its negotiated link with maxLink. A width below maxLink on a GPU or NVMe is possible lane sharing or a slot limit: cross-check any supplied motherboard manual excerpt (M.2/PCIe sharing tables, block diagram, rear-panel layout) before naming a slot. A lower PCIe generation on an idle GPU is normal power saving, not a fault. When every slot is in use and no width is lost, recommend nothing; when lanes are shared, only report the trade-off (for example GPU at x8 because an M.2 slot is populated) and leave the decision to the user. For USB, identify latency-sensitive input (mouse, keyboard, controllers), audio interfaces, cameras and capture devices from kinds, names and the user's notes, which controller (CPU or chipset) and external hubs each uses, and propose a concrete port plan: input devices directly on a CPU-attached controller without hubs, audio and capture on a different controller from high-polling input, storage and low-priority devices (UPS, RGB, dongles) on the chipset or hubs. firmwarePanel is often missing or wrong: with a manual excerpt or a rear-panel photo, name ports by their printed labels and positions; otherwise describe them by controller and port and explain how to identify them physically (move one device and see where it reappears in Device Manager). Gains from moving USB devices are usually small; present them as suggestions to measure, not guarantees. This objective is advice only: no executable capability, firmware setting or physical change is applied by NeuroTune.
